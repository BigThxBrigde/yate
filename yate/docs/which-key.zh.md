# yate which-key（按键提示面板）

[English](which-key.en.md) · **中文**

which-key 面板是 yate 的键位表速查窗口。当一个按键组合（chord）仍在
输入过程中时，面板实时列出所有可接续的下一个按键及其描述；它也可以
被钉住，作为按类别分组的完整键位表。面板位于窗口底部、状态栏正上方，
从不抢占焦点，也从不吞掉任何按键。

---

## 1. 概述（Overview）

面板有两种读法：

- **挂起组合自动弹出**——每次按键派发后，活动键位表会报告目前已键入
  的组合前缀；只要组合仍处于挂起状态，面板就显示该前缀的表头，外加
  一张"下一键候选"网格及各自描述。组合一旦完成（或被取消），面板
  随即隐藏。
- **`<f9>` 钉住式速查**——`<f9>` 触发 `toggle_whichkey` 动作，把整张
  绑定表钉成按类别分组的完整速查页（vim 与 vsc 两张键位表都绑定了
  该键）。钉住期间无论输入什么，速查页都保持显示；再按一次 `<f9>`
  解除钉住。

每次派发后都会重新计算可见性，四个分支互斥、命中即止：钉住的速查页、
vim 的 `ctrl+w` 窗格组合、挂起组合候选，其余情况面板隐藏。

---

## 2. 键位表差异（Keymap differences）

**vim**——自动弹出跟随 NORMAL 模式下真实的组合状态：

- 挂起的寄存器（`"`）、计数、操作符（`d`、`c`……）与前缀都会在键入
  过程中展示可接续的候选（按键入顺序：寄存器、计数、操作符、前缀）；
- `ctrl+w` 窗格组合有自己的一张十四键表：`h` `j` `k` `l` 移动，
  `s` :split，`v` :vsplit，`q` 关闭，`o` :only，`ctrl+w` 循环，
  `+` `-` `<` `>` `=` 调整尺寸——与消息行提示所用的措辞完全一致；
- INSERT 与 VISUAL 模式从不保持组合状态，因此不会弹出候选。

**vsc**——vsc 键位表没有组合状态（无计数、操作符、寄存器），自动弹出
永远不会触发，也没有可触发它的"伪前缀"。它浏览绑定的方式是 `<f9>`
钉住式速查页，整张表按类别分组展示。

---

## 3. 冲突检查（Conflict checking）

`:check-keys` 扫描当前活动键位表，并把报告输出到标题为
"key conflicts" 的输出浮层。报告涵盖两类冲突：

- `duplicate`（重复）——同一按键在表中绑定了多次；后出现的条目会遮蔽
  先前的，使先前绑定永远不会派发；
- `reserved`（保留）——该按键在查表之前就被消耗掉（例如 vim 的硬编码
  分支），所绑定的动作永远无法执行。保留键集合只对 vim 键位表生效，
  其余键位表只扫描重复项。

扫描干净时输出 `keymap: <name> -- no conflicts`；否则以
`keymap: <name> -- N conflict(s) (D duplicate, R reserved)` 开头，
随后每个冲突一行 `<key>  <reason>  action1 -> action2`；只要
reserved 一类非空，报告末尾会追加一句说明。

在原生 vim 键位表上，扫描会报出八条 reserved 行（`<esc>`、
`<ctrl-b>` / `<ctrl-d>` / `<ctrl-f>` / `<ctrl-u>`、`<ctrl-g>`、
`<ctrl-r>`、`<alt-c>`）。这些行是刻意保留的帮助镜像：命令由 vim 内建
分支执行，因此这一行本身永远不会派发——正是末尾说明所讲的情况。
扫描真正要抓的是后来（例如扩展）加在这些按键上的绑定：那种绑定会
悄无声息地永不触发。

---

## 4. 已知限制（Limitations）

- **`<f9>` 的终端可达性**——个别终端会自行捕获功能键，导致 `<f9>`
  根本到不了编辑器，钉住切换在这些终端上无法触发。冲突报告仍可从
  命令行经 `:check-keys` 使用，但面板切换本身尚无命令行回退入口。
- **计数加操作符只显示表头**——vim 的移动命令（`w`、`$`……）是硬编码
  实现，不是绑定表条目，因此键入 `2d` 或 `"a2d` 后面板只列出挂起组合
  本身，没有候选行。
- **暂无 yaterc 持久化**——目前没有配置 which-key 面板的 yaterc 选项，
  钉住状态也不会持久化：重启后速查页默认处于未钉住状态。两者均暂不在
  范围内。
