# 子代理并行执行规则

本规则约束 **AI 助手在本项目里的任务执行方式**，与代码风格/架构规则并列；与其它任何"尽量少用或不用子代理"的默认约定冲突时，以本规则为准。

## 一、硬性要求

**总则：子代理是加速手段，不是交付前提。任何成员失败都不得阻塞主任务——主代理必须始终保留"自己干完"的兜底路径，不得因成员死掉而自动重建团队。**

1. **可拆分的子任务必须并行下发给子代理**，不要串行自己逐个做完。
   "可拆分"的判据：任务能按**互不重叠的文件/模块**切开，且每部分都能独立验证。
2. **同时在跑的子代理不超过 6 个**（含正在收尾的）。超过就分批：等第一批回收后再下第二批，不得超发。
3. **文件独占**：每个子代理只能改自己名下的文件；子代理**不得修改产品源码**（`yate/`），确实需要改就停下来上报，由主代理决定。
4. 主代理（我）保留**监管与收尾权**：开工前定规范与文件边界，收工后统一跑门禁、回填文档、提交。

## 二、下发任务书必须包含

- **唯一规范来源**：指向计划文档 / 映射表（如 `.trae/documents/**`）并声明"以它为准，不要凭常识猜"。
- **独占文件清单**：明确写"只改这些文件，不要动其它任何文件"。
- **验证命令**：可直接复制执行的命令（本项目为 Windows PowerShell，解释器统一用 `.venv\Scripts\python.exe`）。
- **报告格式**：改动清单 + 实际执行的命令与结果 + 未解决项与原因。
- **无写盘能力的兜底**：若子代理没有写文件工具，要求它改为输出"文件:行号 → 原代码 → 新代码"的清单，**不许假装改了文件**。

## 三、运行期纪律（本会话踩过的坑）

1. **spawn 后立刻探活**：用 `send_message` 发一条进度询问；若返回 `Recipient not found` / 成员表为空，说明成员已被运行时回收 —— **不要原样重试同一批**，改为主代理直接执行，并如实报告"子代理零产出"。
2. **成员回报的数据一律独立复核**：主代理重跑该成员名下的测试与 pyright，不得直接引用其自述数字。
3. **并发会互相干扰**：多个子代理同时跑 Textual pilot / 冒烟时会出现 timing 类偶发失败；遇到先重跑确认，再下结论，不许直接改断言。
4. **收尾必做**：全部成员回收（`shutdown_request`）→ 删除团队 → 全量门禁 → 文档回填（含真实前后数字与偏离计划的校准理由）→ 提交。

## 四、报告纪律

- 对用户只汇报**可验证的事实**：实测数字、命令与退出码、剩余缺口。
- 偏离计划（阈值、豁免清单、范围）必须显式列出并给出实测依据，不得粉饰。

## 五、防意外中断与禁止反复重启

> 依据：`cov-round2` 三个成员 spawn 成功、探活消息 `read: true`，但零回信、零产出，整批静默失效（`tests/test_fonts.py` 零 diff、`test_completion_popup.py` 未生成）。以下规则用于消除该失败模式。

1. **spawn 配置必须显式指定，不得吃默认值**：
   - 需要写文件 / 执行命令的成员，显式给 `acceptEdits`（确需时 `bypassPermissions`）。默认权限模式下，成员的写盘/命令动作会卡在无人应答的审批上，表现为"已读不回、零产出"——这是子代理意外中断的头号原因。
   - 只读探索用 `code-explorer`；需要写盘或执行命令的任务必须用团队模式成员。角色与工具能力不匹配时得到的是"零产出"而非报错。
2. **spawn 与探活必须在同一回合内闭合**：下发探活消息后不得结束回合去等用户——回来时成员通常已被运行时回收。
3. **判死条件（满足任一即判死）**：探活返回 `Recipient not found`；成员表为空；探活消息 `read: true` 但数分钟内无回信、名下文件零变化。
4. **判死后不得原样重试、不得"救活"式重建团队**：确需重试时最多一次，且必须先变更配置（权限模式 / 任务粒度 / 批大小）再下发；否则一律改由主代理直接执行。
5. **批大小**：实践按 2~3 个一批下发（硬上限 6）。并发越高，pytest / Textual pilot 互相干扰越重，整批失效的概率越大。
6. **只认落盘结果**：成员声称完成但文件无变化 = 零产出，半成品同样按零产出计；主代理重跑该成员名下测试与 pyright 后才算数。
7. **如实报告**：汇报成员存活数、零产出成员及其名下文件状态；不得把主代理代做的产物记成子代理成果。
